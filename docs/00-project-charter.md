# 00 — 项目章程

## 1. 问题

Minecraft 服务端只能用原版容器搭界面：箱子、漏斗、铁砧、书。视觉上限很低，布局被槽位网格锁死，
每个插件都在发明自己的"物品加标题"约定。想做更丰富的界面，要么给每个服单独写一套客户端模组，
要么用资源包技巧——而资源包无法响应服务端状态。

Cloud Core 把一直纠缠在一起的三件事拆开：

1. **界面长什么样** —— 服务端描述，按玩家解析。
2. **界面做什么** —— 每个事件由服务端决定。
3. **怎么画出来** —— 在轻量客户端模组里实现一次。

服务端掌握状态与权威，客户端掌握像素与输入。任何一方都不假设另一方诚实。

## 2. 用户

| 用户 | 需求 |
| --- | --- |
| 服务器管理员 | 不写 Java 就能上线主题化界面；第三方插件的容器界面保持统一风格 |
| 插件开发者 | 用有文档的协议和少量 Java API 渲染丰富界面，并能扩展新面板 |
| 玩家 | 响应快、不破坏原版行为、不和别的模组打架 |

## 3. 目标

- **G1** 服务端定义界面，支持任意布局：面板、文本、图片、按钮、输入框、列表、滑块、物品网格。
- **G2** 可定制的六类面板：HUD、箱子界面、玩家背包界面、ItemTooltip、自定义页面、Boss 血条。
- **G3** 面板体系可扩展：以后新增面板类型不需要改协议主干，只需要新增适配器和特性位。
- **G4** 替换容器渲染，同时保留槽位语义和原插件的点击逻辑。
- **G5** 页面可以由多个 YAML 片段组合，也可以一个 YAML 就是一个页面。
- **G6** 支持遍历（`repeat`）生成列表和重复元素。
- **G7** 支持自定义字体（客户端本地 CloudCore 目录、资源包和最小内置回退）。
- **G8** ItemTooltip 支持滚轮滚动，并能在滚动时保持与原版一致的交互。
- **G9** 所有状态变更都源于服务端；客户端输入只是请求，不是结果。
- **G10** 为后期动作引擎预留编译、执行和持久化接缝；v1 先实现简单动作列表。
- **G11** 所有配置、协议、文档、资源、渲染和动作错误都写入客户端日志，带稳定错误码、上下文和
  诊断包，方便作者/管理员定位。

## 4. 非目标

- **N1** 服务端下发并在客户端执行的脚本。没有 `eval`，没有下载字节码，没有带副作用的表达式语言。
- **N2** 替换原版物品栏协议。槽位移动保持原版；这正是第三方插件还能正常工作的原因。
- **N3** 反作弊。Cloud Core 只校验界面事件，不管游戏玩法。
- **N4** v1 支持创造模式物品栏。它有不同的界面层级和标签页，后续单独做。
- **N5** 运行时推送字体文件。字体来自客户端本地 CloudCore 目录、资源包或最小内置回退；内联贴图
  不能替代字体提供器。
- **N6** 在原版客户端上渲染。没有客户端模组就做不到。
- **N7** v1 支持 Folia / 区域化线程。
- **N8** 资源包、页面、启动器的统一分发。这些由服务器或插件作者自己的体系负责。

## 5. 设计原则

1. **服务端权威，失败即拒绝。** 未知报文、过期修订号、缺少权限或超出限额 → 拒绝并记录。
2. **核心与平台无关。** 协议和文档模型是纯 Java，即使两端都用 Mojang 映射。
3. **面板是一等公民。** 每种可定制目标都实现为一个 `SurfaceAdapter`，共享同一套文档、状态和输入模型。
4. **一个坐标系只有一个负责人。** 服务端用 GUI 像素描述布局；客户端只在一个适配器里做映射。
5. **原版互操作是功能，不是附加项。** 每个钩子都要窄、可取消、能回退。
6. **渲染默认 NanoVG，原生桥负责原版内容。** 面板、静态文本、图片和特效走 NanoVG；物品、槽位、
   tooltip 内容和输入法走原版。原生 `GuiGraphics` 后端必须随时可回退。
7. **版本敏感代码收在一个文件里。** NanoVG/FBO/合成差异进 `NanoVgBackend` 和 `FboCompositor`，
   原版绘制差异进 `NativeBridge`，面板钩子进各自的适配器。
8. **测量，不要断言。** 文档里的性能数字是目标，直到 `docs/09-testing.md` 给出实测结果。
9. **错误必须可定位。** 每个失败路径都有 `CC-*` 错误码、上下文和客户端日志；服务端诊断摘要
   通过 `DIAGNOSTIC` 下发。没有“静默失败”。

## 7. 约束

- 所有模块使用 Java 21 工具链。
- Minecraft 1.21.11 / Fabric Loader 0.19.5 / Fabric API 0.141.3+1.21.11 / Loom 1.14-SNAPSHOT。
- 客户端使用 `loom.officialMojangMappings()`，不使用 Yarn。
- Paper API 1.21.11；Paper 1.21.11 自身也已切换到 Mojang 映射。
- 核心链路不依赖 ProtocolLib、PacketEvents，也不使用服务端内部 NMS。
- 客户端模组必须能作为普通 Fabric 模组 jar 分发。NanoVG 使用 `lwjgl-nanovg` 及其 Windows/Linux/macOS
  原生库，随模组打包；加载失败时回退原生 `GuiGraphics` 后端。
- 客户端需要额外的 FBO 显存和 GPU 填充预算，默认按 GUI 逻辑分辨率渲染并整数倍放大；FBO 是 GPU
  离屏纹理，不做每帧 CPU 上传或 readback。

## 8. 术语表

| 术语 | 含义 |
| --- | --- |
| **面板（Surface）** | 一个可被服务端定制的渲染目标：HUD、容器、背包、Tooltip、Boss 血条、独立界面 |
| **文档（Document）** | 编译后、带版本号的界面描述（元素 + 样式 + 动作） |
| **页面（Page）** | 作者视角的完整界面，可由一个或多个 YAML 片段组成 |
| **片段（Fragment）** | 被页面包含的 YAML 文件，提供元素、状态、样式或动作的一部分 |
| **修订号（Revision）** | 每个文档单调递增的整数；客户端拒绝非递增的更新 |
| **会话（Session）** | 一个玩家与一个已打开界面的实时绑定 |
| **绑定（Bind）** | 会话与客户端即将呈现的面板之间的关联 |
| **预绑定（Pre-bind）** | 在打开容器之前发送 `UI_OPEN`，由下一个容器界面消费 |
| **持久绑定（Persistent bind）** | 会话不随单次打开结束，例如 HUD 皮肤、背包皮肤、Tooltip 配置 |
| **遍历（Repeat）** | 根据列表状态展开多个元素实例的 DSL 结构 |
| **动作（Action）** | 文档中声明的服务端效果 |
| **动作引擎（Action Engine）** | 后期的服务端动作图执行器，支持分支、循环、等待与持久化状态 |
| **NanoVG 后端** | 离屏渲染 UI 的默认后端，负责面板、文本、图片与特效 |
| **FBO 合成** | 把 NanoVG 渲染的纹理通过原版 GUI 管线贴回屏幕 |
| **原生桥（Native Bridge）** | 用原版渲染器绘制物品、槽位、tooltip 内容和输入法文本 |
